Every command

Everything in this study runs through make. A make target is a short name for one or more shell commands; most of them call a Python module of harness/ or analysis/, which you can also run on its own with python3 -m.

In one sentence: make help lists what you need, make campaign SPEC=... measures, make status watches, and the *-results targets turn raw runs into the tables and figures of the paper.

The six you use daily

You will type these six far more than all the others together. Each one stands for a longer command that you never have to remember.

make. A tool that runs named recipes. make build looks up build in the Makefile and runs the shell commands written under it. The recipes of this project are in make/*.mk, one file per concern, and make help lists the ones meant for you.
CommandWhenWhat happens
make buildAfter pulling or changing bench/Compiles the native runner and the WASM package. A minute the first time, seconds after.
make testBefore every commitWhat CI runs, minus LaTeX: the Rust tests, the Python tests, lint. On the Mac two Linux-only lint steps fail; the rest must pass.
make quick-rq1To see the whole pipeline work, on any machineEighteen tiny runs of the filter in native, Chrome and Firefox, then their progress line. Never a result.
make campaign SPEC=harness/campaigns/<name>.jsonOn the PC, after make env-setupRuns the whole campaign; stop it and run it again to resume.
make status SPEC=...In a second terminal, any timeProgress, failures, ETA. Reads two files, touches nothing.
make results (or all-results)After a campaign, on any machineEvery table and figure of the paper from the raw runs; all-results adds the exploratory campaigns and this guide's numbers.
Why does everything go through make? Because the long commands have twenty flags that must be the same every time (--strict, the 0.25 s threshold, the mask), and a flag typed differently once would make one table silently unlike the others. The recipe is the single place those flags live, and it is committed. The reference below shows what each recipe expands to.

make targets

The Makefile holds only the shared variables and help; the rules live in make/*.mk, one file per concern. A target whose line ends in ## text is listed by make help; one marked #: text is a helper that help hides. Both kinds are in the tables below.

SPEC. The campaign a target works on: a JSON file in harness/campaigns/. Its name key gives the results folder data/raw/<name> and its build key the build variant (baseline, scalar or avx2). Default: smoke.json.

Quick checks (make/quick.mk): never results

Tiny copies of every campaign, to check the pipeline end to end or to watch a run. They keep each real spec's environments, workloads, warm-up, build variant and CPU mask, and shrink the rest (3 runs, few N, 4096², 5 measured iterations). They are "strict": false with no run scope, so they run on any machine without sudo, into data/raw/quick-* (ignored by git).

Campaign commands
