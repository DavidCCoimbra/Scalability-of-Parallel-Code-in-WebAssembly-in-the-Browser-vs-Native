Words of the project

The study has about fifteen words of its own. They name the cells of the experiment, the measurements, and the builds. Every file name, every column in the data and every number in the paper is made of them. This page gives each one with an example; the general words (thread, cache, median) are in Foundations, and the underlined ones open their definition anywhere.

In one sentence: a run times one workload on N threads in one environment, 30 runs make a configuration, all the configurations make a campaign, and from 30 run values come the speedup and its interval.

Environment, workload, N, k

Four choices name a cell of the experiment. Every run belongs to exactly one cell:

Environment

Where the code runs: native (a normal Linux program), chrome or firefox (the same code as WebAssembly inside that browser). The three names are the values of the env column in the data. Three runtimes, one source.

Workload

The job being timed: filter (the blur), hist-atomic (the histogram with a shared tally) or hist-local (private tallies, the control). The exploratory campaigns add hist-atomic-private, hist-atomic-packed and two sorts. The workloads.

N

How many worker threads the run uses: 1, 2, 4, 6, 7 or 8 in the main campaign, never more than the 8 fast cores. The decisive comparisons are at N = 8; 7 is there to see where Firefox starts to bend.

k

How many distinct grey shades the histogram's input has: 1, 4, 16 or 256. It sets how hard the threads fight over the shared counters. The filter has no k; its input is noise. k: the contention dial.

Run, iteration, configuration, campaign

Run

One fresh start of the program (or one fresh start of the browser) that times the workload and writes one CSV file. The run is the unit everything is counted in: 30 runs give 30 values, not 300. The run is the unit.

Iteration

One timed pass over the whole image inside a run. A run does a few warm-up iterations that are not counted, then 10 measured ones. The run's value is the middle one (the median) of the 10.

Configuration

One cell (environment, workload, k, N) with its 30 runs. The main campaign has 162 configurations; "the filter in Chrome at N = 8" is one of them.

Campaign

Every run of a whole experiment, run in one seeded random order and kept in one folder, data/raw/<name>/. The main one, campaign-v3, has 4860 runs. Campaigns, specs and resume.

Primary and exploratory

The 10 comparisons that answer RQ1 and RQ2 are primary: they were fixed before the data and get a stricter bar. Everything else (weak scaling, SIMD, E-cores, cutoffs) is exploratory: reported, but with the ordinary bar and no claim of having been planned.

Pilot

A small early campaign used to pick a setting (how many warm-up iterations, the image size, the start delay), on an earlier build. Pilot numbers justify a decision; they are never reported as results.

Build, tag, variant

Build

The exact compiled program: one native binary and one WASM module from one version of the source. Two builds can differ by a single line of machine code, and that can change a timing, so runs from different builds are never mixed in one comparison.

Tag

A name on the exact version of the code a campaign ran: measured/v3 is the one every reported number comes from. The build's hashes are recorded with every run, so a run can always be traced to its code. Builds and tags.

Variant

A build switched by a compile-time feature for an exploratory question: scalar (no SIMD), avx2 (wider native SIMD), pad64 (half the padding). The default build is baseline.

The numbers

From the 30 values of a configuration, the study reports:

  • TN: the typical time with N threads, an average of the 30 run values that respects ratios (the geometric mean; why that one is in Reading the numbers).
  • Speedup SN = T1 / TN: how many times faster N threads are than one, each environment against itself. 8 means perfect use of 8 threads; below 1 means 8 threads are slower than one.
  • Efficiency = SN / N: the share of perfect. 1 is perfect, 0.5 means the threads are half idle on average.
  • Interval: the range the value would likely fall in if the 30 runs were done again, found by the bootstrap (How sure can we be).
  • Time ratio browser / native: the same question in seconds, because a speedup alone can hide a slow start (Ratios).

What to remember. A run is one program start and one value. Environment, workload, k and N name its cell; 30 runs make a configuration; a campaign is all of them in one shuffled order, on one tagged build. Speedup compares an environment with itself; the time ratio compares it with native.
