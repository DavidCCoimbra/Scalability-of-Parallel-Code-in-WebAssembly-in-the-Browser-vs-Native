Reproduce the tables and figures

No number of the paper is typed from memory. Each one is in a table that a command wrote from the raw runs, and each command is a make target. This guide shows you the chain from data/raw/*-v3 to data/tables/*-v3 and paper/figures/, how to run it and check it, and a table that recomputes the main numbers from the committed data every time you open the page.

The chain

Why

Why must every number be reproducible from a command? Because a number typed from a terminal is a number nobody can check: not a reviewer, not the author in a month. With the chain below, "where does 0.42 come from?" has one answer, a file and the command that wrote it, and the table at the end of this page recomputes the main numbers from those files every time it is opened.

Pick a box above.

The steps, for the main campaign, are exactly the lines of make results:

  1. Check. analysis.datacheck writes the quality report and stops the chain if a run is missing, failed or disagrees on its checksum (The data check).
  2. Join. harness.collect joins every run into one table, a convenience for exploring; the statistics read the raw folder themselves.
  3. Scale. analysis.v0: one value per run (the median of its 10 measured iterations), the geometric mean over the 30 runs, speedup and efficiency with bootstrap intervals.
  4. Infer. analysis.results: the contrasts of the analysis plan, with --strict and the 0.25 s foreign CPU threshold applying the plan's exclusions, and Holm over the 10 primary contrasts.
  5. Cross-check. analysis.robustness (Mann-Whitney and Cliff's δ) and analysis.karp_flatt.
  6. Draw. analysis.figures and analysis.distributions into paper/figures/.
  7. Write. paper/final/paper.tex includes the figures and quotes the tables.
  8. Guard. make tables-check does all of the above again and fails if any table differs from the committed one; CI runs it on another machine whenever the analysis, the harness or the data change.

The other campaigns follow the same pattern in extras-results (extras, weak, SIMD, hybrid), cutoff-results, grain-results, perf-results and v3-results (the sequential references, the engine arms, the grain by threads and the counters of the loop). The whole thing, from a clean checkout with the raw data:

git checkout main
make all-results           # every table and figure of every campaign
make tables-check          # the same, then fail if a committed table differs
make explainer             # this documentation's data.js

Why the tables carry a sidecar. Each -scaling.json and -contrasts.json records the settings (summary, centre, bootstrap seed and resamples) and the commit that wrote it, in a fixed key order. Regenerating a table on the same data changes only the commit and the time stamp, so a diff shows at once whether a number moved.

Every paper number, its file

The main numbers of the study, as the paper and this documentation state them, next to what the table gives when this documentation reads it. The "Table gives" column is computed in your browser from assets/data.js, which is itself generated from the tables, so a mismatch here means the text and the data disagree.

Numbers not in the table above are in the same files. The paper's run counts come from the specs (Every campaign), the machine description from data/raw/campaign-v3/sysinfo/, the machine code of the atomic add from data/probes/engine-code/, the probe times from data/probes/atomic-increment/, and the pilot numbers that justify a design decision from the pilot campaigns and their ADRs.

The numbers of this documentation

The pages of this documentation contain no measured number in their text. They draw tables and charts from assets/data.js, which one script writes:

Part of data.jsRead from
tablesEvery CSV in data/tables/*-v3/ (one key per file, one object per row), except the per-run perf table
sourcesThe path of each of those CSVs: the "source:" links under every chart
forkJoinThe calibration-warm rows of every run in data/raw/campaign-v3: per environment, N and probe, the median of the run medians and the mean of all calls
coreCheck, atomicIncrementThe per-core check (data/checks/core-check/runs) and the atomic increment probe (data/probes/atomic-increment/passes.csv): checks, never results
runMediansThe per-run medians of three configurations, for the bootstrap widget
codeEvery excerpt a page asks for with data-code="file|first line|lines", read from the repository
 
make explainer                                 # python3 -m scripts.explainer_data
python3 -m scripts.explainer_data --check      # exit 1 if data.js is out of date

An excerpt is found by the text of its first line, not by its line number, so it follows the code when lines move; if that text disappears, the script stops instead of showing the wrong lines. Run it again after any change to the tables or to the code a page shows.
