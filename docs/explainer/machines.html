Programs, processes, threads and cores

Before any number in this study makes sense, four words have to be clear: a program, a process, a thread and a core. This page explains them with a kitchen. No project numbers here, only the ideas the rest of the guide leans on.

In one sentence: a program is a recipe, a process is one kitchen cooking it, threads are the hands working in that kitchen, and cores are how many hands the building really has.

A program and a process

A program is a file of instructions sitting on disk. It does nothing by itself, like a recipe in a drawer. When you start it, the computer makes a process: a running copy of the program, with its own private memory (the space where it keeps its numbers, images and text while it runs).

Picture it. The recipe is the program. A kitchen with that recipe pinned on the wall, ingredients on the counter and a cook at work is a process. Start the same program twice and you get two kitchens, each with its own counter; what one cook chops, the other cannot see.

Why does the study care? Because every measurement here is of one whole process, started fresh. A process that has been running for a while has warmed-up memory and half-done work in it; a fresh one has nothing. Runs, warm-up and order explains why that matters.

Threads: several hands, one memory

Inside one process, work can be done by more than one thread. A thread is one line of work going on at a time: it reads an instruction, does it, reads the next. Every thread of a process sees the same memory. That is the whole point of threads, and the whole danger.

Picture it. One kitchen, one counter, several cooks. They do not have to pass bowls to each other: whatever one puts on the counter, the others can use at once. But two cooks reaching for the same bowl at the same moment will spill it, unless they agree on who goes first.

So threads give you two things at once:

  • Speed, when the work splits into pieces that do not touch each other. Eight cooks, eight separate dishes, no waiting.
  • Trouble, when they touch the same thing. Then they must take turns, and taking turns costs time. This study measures exactly that cost, in RQ2.
Shared memory. Memory that several threads can read and write. In a browser it is rare and needs special permission; Three runtimes, one source says how the project gets it.

Cores: how many hands can work at once

A thread is a line of work; a core is the part of the chip that can actually do work. One core does one thing at a time. A chip with 8 cores can run 8 threads truly at once. Start 16 threads on it and they take turns on the 8 cores: it looks like all 16 are running, but each gets half the time.

Picture it. Cooks are threads; stoves are cores. Eight stoves, eight cooks: all cook at once. Eight stoves, sixteen cooks: every cook spends half the evening waiting for a stove.
Why does the study stop at 8 threads? Because its machine has 8 fast cores for the test. With 9 threads, one of them would be waiting for a core, and the time would go up for a reason that has nothing to do with the browser or the code. The machine and its controls shows how those 8 cores are kept free.

One more thing to know: many chips today mix fast cores and slow cores on the same chip (Intel calls them P-cores and E-cores). A thread that lands on a slow core takes longer through no fault of its own. The study keeps the test on the fast ones, and tries the slow ones only in a side experiment (P-cores plus E-cores).

The clock, turbo and SMT

How fast a core works depends on its clock: how many steps it takes per second (3.2 billion a second is "3.2 GHz"). Three things change that speed under you:

  • Turbo. A core runs faster than its base clock while the chip is cool and slows down when it heats up. The same work, done twice, takes different times.
  • The governor. The operating system may lower the clock to save power when it thinks nothing important is happening.
  • SMT (hyper-threading). One core pretends to be two, so two threads share it. They both run, but each gets less of the core.
Picture it. Turbo is a cook who sprints at the start of the shift and slows as the kitchen heats up. The governor is a manager who dims the stoves when the restaurant looks empty. SMT is two cooks sharing one stove: both are "cooking", neither at full speed.
Why turn all three off? This study compares how much faster 8 threads are than 1. If the clock changed with the number of threads or with the temperature, part of that "faster" or "slower" would come from the clock, not from the code, and we could not tell the two apart. With turbo off, the governor fixed and SMT off, every core runs at the same speed all the time, and 8 threads really get 8 cores. The machine shows the settings.

What to remember

What to remember. A process is one running program with its own memory. Its threads share that memory, which makes them fast when they work apart and slow when they touch the same thing. A core does one thread at a time, and the study gives its 8 threads 8 cores that always run at the same speed, so that time only changes when the code does.
